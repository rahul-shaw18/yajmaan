End-to-End User & Pandit Sequence Flow

Walks through the client-server interaction from login and address selection to booking, FCM push alerts, and first-accept locking.

sequenceDiagram
    autonumber
    actor Customer as Customer (App)
    participant API as Django REST API
    participant DB as Database (Postgres)
    participant FCM as Firebase Cloud Messaging
    actor Pandit1 as Pandit 1 (Accepted)
    actor Pandit2 as Pandit 2 (Rejected/Late)

    Customer->>API: 1. POST /api/v1/auth/request-otp/ {phone}
    API-->>Customer: OTP sent (Dev fallback: 123456)
    Customer->>API: 2. POST /api/v1/auth/verify-otp/ {phone, otp}
    API-->>Customer: JWT Access Token + Profile
    Customer->>API: 3. POST /api/v1/users/addresses/ (Coordinates + set default)
    API-->>Customer: Address saved & active

    Customer->>API: 4. GET /api/v1/home/
    API-->>Customer: Home feed (Categories, Popular Poojas, Artis, Horoscopes)
    Customer->>API: 5. GET /api/v1/catalog/services/{slug}/
    API-->>Customer: Single pooja details, Samagri list, Scripture source

    Customer->>API: 6. POST /api/v1/bookings/ (WITH_SAMAGRI, PAY_NOW)
    API->>DB: Save Booking (SEARCHING_VENDOR) + Snapshots + Payment
    API->>API: Calculate eligible vendors (Radius + Origin Priority)
    API->>FCM: Dispatch push notification (NEW_BOOKING_REQUEST)
    FCM--)Pandit1: High-priority push alert
    FCM--)Pandit2: High-priority push alert

    Pandit1->>API: 7. POST /api/v1/bookings/{id}/accept/
    API->>DB: Atomic SELECT FOR UPDATE on Booking
    API->>DB: Set vendor = Pandit1, status = ACCEPTED
    API-->>Pandit1: 200 OK (Booking assigned to you)
    API->>FCM: Push notification to Customer (Vendor Assigned)
    FCM--)Customer: "Pandit has been assigned to your booking"

    Pandit2->>API: 8. POST /api/v1/bookings/{id}/accept/
    API->>DB: Check Booking Status
    API-->>Pandit2: 409 Conflict (Already accepted by another vendor)

Assignment Engine Decision Logic

Visualizes how the system filters candidates by distance, ranks by origin match, and handles first-accept concurrency.

flowchart TD
    Start(["New Booking Created"]) --> Snapshot["Create Address and Spiritual Origin Snapshot"]
    Snapshot --> Query["Query Vendors with Category Skill Match"]
    
    Query --> ActiveCheck{"Is Active and Available?"}
    ActiveCheck -->|No| Skip["Skip Vendor"]
    ActiveCheck -->|Yes| DistCalc["Compute Haversine Distance: Vendor GPS to Booking GPS"]
    
    DistCalc --> RadiusCheck{"Within Vendor service radius?"}
    RadiusCheck -->|No| Skip
    RadiusCheck -->|Yes| PriorityScore["Calculate Priority Score:
- Origin State Match: +50
- Origin City Match: +50"]
    
    PriorityScore --> Sort["Sort Candidates by:
1. Priority Score Desc
2. Distance Asc
3. Rating Average Desc"]
    
    Sort --> PushFCM["Send High-Priority FCM Push to Vendor Devices"]
    PushFCM --> LogDispatch["Record in booking_dispatch_logs (DISPATCHED)"]
    
    LogDispatch --> WaitVendor["Vendor App Displays Alert Prompt"]
    
    WaitVendor --> VendorAction{"Vendor Action?"}
    VendorAction -->|No or Reject| MarkReject["Update Log: REJECTED"]
    
    VendorAction -->|Yes or Accept| AtomicLock["Begin DB Transaction:
SELECT FOR UPDATE on Booking"]
    
    AtomicLock --> CheckStatus{"Is Vendor Assigned or Status is ACCEPTED?"}
    CheckStatus -->|Yes| Conflict["Return 409 Conflict:
Already accepted by another vendor"]
    CheckStatus -->|No| Assign["Assign Vendor and Set Status to ACCEPTED"]
    
    Assign --> ExpireOthers["Update Other Dispatches to EXPIRED"]
    ExpireOthers --> NotifyCustomer["Send FCM Push to Customer Device:
Pandit Assigned"]
    NotifyCustomer --> Finish(["Booking Confirmed"])
